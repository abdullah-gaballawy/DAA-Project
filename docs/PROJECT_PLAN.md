# Execution plan (illustrative weeks, NOT an official course deadline)

| Phase | Focus | Exit gate |
|---|---|---|
| Week 1 | Confirm roster, I/O assumptions, GitHub repo, independent task designs | 8 reviewed task design notes |
| Week 2 | Implement tasks 01-04, test and review | Normal and edge paths covered |
| Week 3 | Implement tasks 05-08, test and review | All eight solvers produce valid outputs |
| Week 4 | Independent checks, screenshots, report/presentation, rehearsal | Correct complexity analysis, clickable URLs, <=20m demo |

Parallelization by task is a suggestion; group size can be fewer than eight. Reserve integration review time for tasks 05, 06 and 08, where correctness/optimality or coloring constraints may need substantial proof.

## Definition of Done per task

- API matches signed-off interface
- Required technique demonstrated
- Code passes reviewed automated tests
- Generated output independently checked where possible
- Valid cases + impossibility/edge paths covered
- Minimum/optimality requirement justified when stated
- >=3 real input/output screenshot pairs
- Actual time and space analysis in report
- Presentation example and speaker assigned
